## 2. How the failure suite avoids luck

- **Contention is forced, not hoped for.** A `RowLockGate` holds `UPDLOCK` on one row from a separate connection. The test starts
  each competing request, then polls `sys.dm_exec_requests` until SQL Server itself reports that many requests queued behind the
  gate (following the blocking chain), and only then releases them together. Arrival orders are enumerated (all 6 for three
  operations). No test depends on a sleep to create the race.
- **Faults go through the real pipeline.** A fault plan keyed by an `X-Test-Op` header injects an exception into the EF command or
  transaction interceptors of the running application: after a specific statement, before COMMIT, or after COMMIT.
- **One fault is real.** `TransactionBoundaryTests.A_connection_severed_mid_checkout_…` runs `KILL` on the checkout's live SQL
  connection while its transaction is open.
- **Constraints are hit directly.** `DatabaseConstraintTests` writes each impossible row with plain SQL and asserts the *name* of the
  constraint that refused it (an overlapping CHECK cannot hide a missing one).
- **The deployment artifacts are executed.** `DeploymentScriptTests` runs `LumaBeauty.sql`, `provision.sql`, both grant scripts and
  `verify-runtime-permissions.sql` as the identities they are written for.

### What is real, simulated, and unavailable

| Fault | Status |
|---|---|
| Row-lock contention between requests | **real** (SQL Server blocking) |
| A connection killed mid-transaction | **real** (`KILL`); the server reports error 596, which is not retryable, so the answer is a 500 with nothing left behind and the key reusable |
| Impossible rows written behind the application's back | **real** |
| Restore from backup, restart, certificate-protected key ring | **real** (`Rehearse-Release.ps1`); rotating the key-ring certificate was observed once by hand on the packaged copy (checklist 3.10) |
| The deployment guide's own commands | **real** wherever IIS and a second Windows account are not needed (PowerShell parsing, key generation, `robocopy`, `icacls`, backup-folder rights, administrator creation: checklist section 6); **unexecuted** for the IIS cmdlets, `appcmd` and `runas` (checklist section 7) |
| Exception after a statement / failure before COMMIT / lost COMMIT acknowledgement | **simulated** at the EF interceptor (for the lost acknowledgement the real COMMIT executes and the client then sees an exception) |
| A network partition between COMMIT and its acknowledgement | **unavailable**: it cannot be produced on one machine without a TCP proxy; the simulation above is the substitute |
| SQL Server restart or failover during a transaction, a full disk, a deadlock victim | **not exercised** |

## 6. Failures the suite found, and what changed

| Found | Fixed by |
|---|---|
| A lost COMMIT acknowledgement made the runner execute the operation again (a checkout twice, a relative stock adjustment twice) | the runner never re-executes after COMMIT was sent; it verifies in a fresh scope or answers 503 `OutcomeUnknown` (DECISIONS D-TX-6) |
| A duplicate submission racing the first attempt failed at once | a bounded wait (`Checkout:LockTimeoutSeconds`), then replay, take-over or `CheckoutInProgress` |
| Stock audit rows could record a previous stock that was already stale | `UPDATE … OUTPUT deleted/inserted`; audit rows carry the order id |
| The database accepted impossible orders and coupon counters | nine CHECK constraints and restricting foreign keys (D-P7-1) |
| Nothing ever removed finished idempotency rows or dead guest sessions | the retention service |
| Skin-type filter returned 500; saving banners returned 500; a banner could name a missing coupon | `PrimitiveCollection` mapping; banner save and validation fixed |
| Upload of a renamed non-image or an oversize image returned 500 | 400 `ValidationFailed` on `file`; 413 above the host limit |
| A copied cookie still worked after logout | the security stamp is rotated and checked on every request |
| A fractional quantity (1.5) returned 500 | `InvalidQuantity` |
| An order or attempt lookup by a visitor with no identity said 401 where ACCEPTANCE A-21 requires 404, and the guest session could expire before the 30-day retention counted from placement | 404 for every non-owner; the guest session is renewed at placement |
| Variants of an admin-created product came back in random order | a stored position (`SortOrder`) |
| The inventory screen could not issue an exact-count adjustment (no row version was exposed) | `variants[].version` on admin reads |
| The committed deployment script failed under `sqlcmd` (session options for the filtered indexes; a backfill referring to a column added in the same batch) while `MigrateAsync` passed | a session-options header and `EXEC` in the migration; `DeploymentScriptTests` executes the file |
| The readiness check could not notice a database created with the wrong collation | collation check in `/health/ready` and at Development start-up |
| A rate-limited request had an empty body, errors written by middleware were `application/json`, a missing script or image returned the HTML shell, API responses had no `Cache-Control` | the standard problem body with `Retry-After`; `application/problem+json` everywhere; 404 for missing files; `no-store` on `/api` and `/health` |
| MARS made EF log a savepoint warning on every transactional save | the connection strings no longer enable it |
| The deployment guide gave folder permissions to `IIS APPPOOL\<name>` before the pool existed (found by review: IIS cannot run here) | the pool and site come first (guide section 5, step 2) |
| The guide's administrator command, run as written, left a trailing space in every value (`set NAME=value && …`) and the host refused to start; its one-shot `runas` windows close together with their output | the schema, administrator and catalog steps run in one window of the deployment identity with `$env:` variables, and the guide warns against the one-liner |
| The guide's first backup fails where the backup folder does not grant the SQL Server service account (OS error 5) | the guide says so and gives the grant |

## 7. P7.2 — the browser suite

Real Chrome drives the built storefront against a fresh API publish and a fresh `LumaBeauty_E2E_*` database, every user-visible
flow in **both languages**, with the page failing on any console error, failed request or unexpected HTTP status.

| Spec | Flows |
|---|---|
| `storefront-catalog`, `storefront-cart`, `storefront-quote` | home, browse, search (English and Arabic), filters, sorts, paging through the whole catalog, product modal (shades, sizes, stock), cart, coupons, free-delivery boundary at 600 EGP |
| `storefront-checkout`, `storefront-lost-response` | address validation in both languages, guest order, confirmation, hard reload, a stranger's 404, changed-price re-acceptance, lost-response recovery |
| `customer-account`, `customer-switching` | registration, sign-in, addresses, wishlist, order history, cancellation, account switching in one tab |
| `admin-access`, `admin-dashboard`, `admin-products`, `admin-inventory`, `admin-promotions`, `admin-orders`, `admin-layout` | admin entry points, metrics, product create/edit/archive with variants and uploads, stock adjustment (delta, exact count, conflicts), coupons, banners, fulfilment transitions, cash collection |
| `storefront-layout-a11y`, `storefront-states` | RTL/LTR, no horizontal overflow at 1280x800 and 390x844, accessible names, focus trap and Escape, keyboard checkout form, empty/loading/error/offline states, no hidden fallback to mock data |

The two placeholders the first suite carried (`todo`: the missing variant version, and the 500 on a renamed non-image) are now
real assertions and pass. Defects the browser walk found in the storefront were fixed in the sources (admin entry points shown only
to administrators, the fake newsletter and fallback hero removed, cents preserved in prices, account-switching leaks, localisation
and accessibility gaps).
